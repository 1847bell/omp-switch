# OMP Switch v1.0.2

本次版本汇总 `fork/maintenance` 分支自 v1.0.1 以来的更新：MCP 条目管理、可恢复的会话删除，以及维护分支自动打包。

| OMP-Switch-1.0.2-win.zip | Windows x64 | 便携版，解压后运行 |
| OMP-Switch-1.0.2-linux.AppImage | Linux x64 | AppImage 便携版 |
| OMP-Switch-1.0.2-linux.deb | Linux amd64 | Debian / Ubuntu 安装包 |

## Added（新增）

- 新增 MCP 条目管理和可恢复的会话删除。
- **MCP 配置管理**：在当前 Profile 的主 `mcp.json` 中按服务条目新增、重命名、编辑或删除配置；编辑窗口分别提供 Key 和 JSON Object 输入，不覆盖无关条目、根字段及未知字段。
- **MCP 安全保存**：保存前校验 JSON 并确认差异，写入前复核原始文件哈希、创建本机快照；切换页面保留草稿，刷新或切换 Profile 时确认是否丢弃修改。
- **单条及批量会话删除**：确认后将会话 JSONL 移至系统回收站，同时清理会话列表、全文搜索及用量索引；全选仅覆盖当前筛选下已加载的条目。外部修改会阻止删除，批量失败项保留选中以便重试。
- **Windows 便携版单独打包**：`pnpm package:win:portable` 清理旧的 `dist/` 后仅生成便携 ZIP。

## Changed（调整）

- 导航与 `Ctrl+1` 至 `Ctrl+8` 按显示顺序统一为：模型、角色、提示、技能、MCP、会话、用量、网关；`Ctrl+5` 直达 MCP。
- 仓库元数据、安装链接、发布工具和更新检查指向 `1847bell/omp-switch`；历史发布说明及已有软件包标识保持不变。
- 推送 `fork/maintenance` 后自动运行 Windows、Linux 打包及验证；其他分支和 Pull Request 不执行 CI 安装包打包。正式版本仍通过 `v*` 标签触发独立发布流程，并创建待审核的 Release 草稿。

## Fixed（修复）

- 未设置 `OMP_UPDATE_ED25519` 时，发布流程不再尝试上传不存在的签名文件；安装包仍可上传到 Release 草稿，未签名的更新清单不会发布。

## 安全与限制

- MCP 保存不会执行命令、启动或连接服务，也不会读取 OAuth 数据库；不迁移旧配置、不修改项目配置。修改后需在 OMP 中重新加载 MCP。
- MCP 配置及本机快照可能包含敏感值，请勿上传。MCP 快照独立于 models/config 的快照恢复界面。
- 删除会话前请先停止 OMP 使用目标会话。附件目录不会删除；回收站不可用时不会降级为永久删除。从回收站恢复文件后可重新建立索引。
- 安装程序仍未签名。应用内签名更新检查需要另外配置与应用公钥匹配的 `OMP_UPDATE_ED25519`，未配置时不会生成签名更新清单。
- GitHub Actions 自动构建并上传发布文件，但只创建 Release 草稿；审核后仍需手动发布。WinGet 和 Chocolatey 的渠道发布不等于 GitHub Release 发布。
