## Fixed（修复）

- 修复网关首次新建无响应，并改善窄窗口布局与凭据自动绑定。
- **编辑布局**：没有已保存网关池时直接显示全宽草稿；端口输入与保存按钮同行。上游卡片集中显示排序、启用、测速和删除操作，模型、认证与凭据字段带有可见标签，按编辑区宽度切换双列或单列。
- **自动绑定凭据**：新建或添加安全库上游、切换模型或认证方式时，自动识别供应商已保存的 Windows 凭据桥、Linux libsecret / age API Key 命令引用。凭据 ID 只读，不读取密钥或执行命令；无法识别唯一引用时清空旧绑定并提示先保存供应商 API Key，阻止误用其他供应商的凭据。打开已有池保留原绑定，OMP OAuth 不使用安全库 ID。
- **请求与流式响应**：上传完成不再被误判为客户端取消；真实断连会释放上游请求和响应流。空闲超时覆盖响应体读取，健康 SSE 流持续续期，下游背压期间不误判上游超时；丢弃的测速或重试响应会主动取消，不在已开始转发后切换上游。
- **响应头**：Node fetch 解压后的 JSON / SSE 不再保留失效的压缩编码或长度，未支持的编码链仍保留原始字节及对应元数据。
- **Profile 与实时配置**：网关池、历史测速和运行归属按 Profile 隔离；运行中保存会先准备新供应商解析器并持久化，再应用路由。切换 Profile、保存、启动及停止串行处理，失败保留原服务，已接收请求继续使用其原有解析器；旧页面不能停止另一 Profile 的新服务。
- **共享端口与连接信息**：每个 Profile 使用一个独立保存的监听端口，冲突或无效的旧端口要求明确选择；运行中改端口需先停止。刷新或重进页面可以恢复当前 Profile 正在运行的网关 token，其他 Profile 和公开 HTTP 端点不能获取它。
- **上游管理与测速**：上游 ID 不复用，编辑时保持输入焦点，重复 ID 在保存前拒绝。启用状态与优先级在保存后生效；测速只针对已保存且未修改的启用上游，逐项报告失败，结果对应被测配置且不隐式保存或改变路由。
- **删除与持久化**：确认删除仅影响当前 Profile 的池、统计和测速历史，不删除共享凭据或监听设置；迟到的测速和请求不能重建已删除记录。JSON 元数据在同一队列事务中修改和原子持久化，失败保留最后耐久状态，避免配置、目录导入、价格及历史记录并发覆盖。更新检查在接受下一次检查前等待退避标记写入完成。

## Changed（调整）

- 标签推送只构建资产并创建待审核 Release 草稿；CLI 容器的版本及 `latest` 镜像改为正式发布 Release 后才构建、验证并推送到 GHCR，避免草稿阶段提前公开该渠道。

## 使用与安全

- 网关仍仅监听本机并要求 Bearer token。将本机 `/v1` 地址、网关 token 和池的虚拟模型 ID 配入 OMP 后再选择该模型；上游需与所用 Chat 或 Responses 协议兼容，健康检查不代表真实推理一定可用。
- token 保存在应用数据目录并跨重启复用；关闭图形窗口不会停止正在运行的网关，终止应用进程则会中断服务。
- 安装程序仍未签名。仅在配置与应用公钥匹配的 `OMP_UPDATE_ED25519` 时附带签名更新清单，不降低签名校验要求。
- GitHub Actions 只创建 Release 草稿。资产和校验值审核完成后仍需手动发布；本次准备不执行正式发布，也不更新依赖公开资产哈希的软件包渠道。
