## 第二组：转发与资源生命周期（P2）

### G05 响应头之后取消与超时失效

- [x] 保持上游响应体生命周期内的取消与超时控制，并在下游断连时释放上游流。
- 证据：**直接转发层实测确认**。真实 SSE 首帧后 abort，超过配置的 40ms，观察至 100ms，上游连接仍未关闭。
- 位置：`gateway.ts` 的 `forwardGatewayRequest` finally（约 250–252 行）、`copyResponse`（约 278–294 行）。
- 原因：fetch 返回响应头后就移除 abort 监听并清除 timer；下游关闭没有配套销毁上游源流。
- G01 已覆盖真实 HTTP 下游断连时销毁上游流；G05 将选定响应的生命周期交给受控响应体，在 EOF、读取错误、调用方取消或超时时释放 reader、timer 与 abort 监听。
- 验收：正常 SSE 可持续读取至 DONE；客户端在首帧后取消能关闭上游；停滞流按明确的超时语义结束；已有响应字节后不切换上游、不重复响应、不产生未处理异常。
- G05 修复前回归：新增 7 项中 5 项失败，真实 HTTP 确认响应头后/首帧后取消、直接转发停滞响应体及 HTTP Chat/Responses 停滞 SSE 都未及时关闭上游。
- 本轮超时语义：每次上游尝试使用空闲期限；收到响应头及每个正文块后重新计时，正常持续输出可跨越多个期限。选定响应后的正文超时/错误只终止当前流，不再次故障切换。

### G06 压缩响应头与正文不匹配

- [x] 保证转发的 `Content-Encoding` 与实际正文编码一致。
- 证据：**直接转发层实测确认**。gzip 上游经 Node fetch 返回的正文已解压，但头仍是 `gzip`；二次 gunzip 得到 `Z_DATA_ERROR`。
- 位置：`gateway.ts` 的 `RELAYED_RESPONSE_HEADERS`、`copyResponse`（约 25–33、280–283 行）。
- 验收：G01 修复后，通过真实 HTTP 网关请求 gzip 上游，客户端可正常读取 JSON；普通和流式响应不受影响。
- 修复前通过真实 HTTP 网关运行新增压缩回归：15 项中 10 项失败、5 项通过。gzip（含别名及大小写）、deflate、Brotli、Zstandard、组合编码的 JSON 和 gzip SSE 因客户端重复解压而失败；直接调用仍携带过期的编码与压缩长度头。
- 原生 Fetch 边界实测：当前 Node v24.14.0 只在所有编码均受支持时解码整个编码链；未知编码、含未知编码的组合及 `x-deflate` 正文保持原样，修复需保留这类响应的编码信息。
- 修复：在受控响应体构造边界统一规范化直接调用及 HTTP 返回；仅对 Fetch 已解码的完整编码链移除 `Content-Encoding` 和原压缩 `Content-Length`。不重新压缩、不缓冲完整正文，未解码编码链继续保留元数据。
- 兼容性补充：上游 [Undici 7.11 发布记录](https://github.com/nodejs/undici/releases/tag/v7.11.0) 与 [实现 PR](https://github.com/nodejs/undici/pull/4238) 确认 Zstd 解码并非早期 Node 24 的固有能力；7.8 源码没有该分支。真实 HTTP 配合旧版 Fetch 语义适配器复现固定编码表会误删 Zstd 元数据，已改为按内置 Undici 版本判断 Zstd 能力，不抬高项目 Node 24 最低版本。

### G07 探测及故障切换时未释放丢弃的响应体

- [x] 先复现连接/响应体是否泄漏，再为被丢弃的响应建立明确的消费或取消路径。
- 证据：**真实 HTTP 回归确认**。初轮新增 6 项中 4 项失败：重复 200/429/503 探测及重试至最终 503 流后，已丢弃的无限响应体连接在 2 秒内未关闭。其余两项在该轮关闭，不据此推断存在可靠释放路径。
- 位置：`gateway.ts` 的 `probeGatewayUpstream`（约 131–138 行）、`forwardGatewayRequest` 的重试分支（约 237–239 行）。
- 复现建议：假上游立即返回 200 或 429 响应头，正文持续不结束；观察探测返回、故障切换后该连接是否释放。
- 验收：探测及重试不会遗留无限响应体或活动连接；最后一个正常返回给客户端的响应仍可读取。
- 确定性复现：测试透明包装真实 Fetch，保留原始 Response 引用，避免 GC 偶然关闭连接掩盖泄漏；修复前新增 6 项全部失败。覆盖重复成功/失败探测、429/503 丢弃响应体，以及最终 200 JSON、200 SSE、503 SSE 的生命周期边界。
- 修复：探测的 finally 主动 abort 请求；转发尝试仅在未把响应体生命周期交给调用方时 abort 并清理 timer/监听。沿用已有 AbortController，不吞取消异常、不新增正文缓冲或释放抽象，最终响应沿用 G05 的受控正文生命周期。
